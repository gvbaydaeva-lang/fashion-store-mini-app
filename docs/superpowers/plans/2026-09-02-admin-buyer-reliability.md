# Надёжность админ-панели и пользовательского каталога — план реализации

> **Для AI-агента:** перед выполнением этого плана использовать `superpowers:subagent-driven-development` или `superpowers:executing-plans`. Все пункты отмечаются через `- [ ]`; после каждой задачи запускать её проверку и только потом переходить дальше.

**Цель:** устранить найденные ошибки в server-backed админ-панели, синхронизировать её с пользовательским каталогом и подготовить безопасный серверный путь заказа без ложного заявления о production-ready состоянии.

**Архитектура:** сохранить один vanilla-JS Telegram Mini App. Продавец работает через защищённый `admin-api`, покупатель читает только опубликованные данные через `catalog-api`. Изменения товара и связанных записей должны выполняться транзакционно на сервере; файлы Storage загружаются во временную область и привязываются к товару только после успешного сохранения. Локальные черновики остаются восстановлением после ошибки, но не источником истины.

**Стек:** HTML, CSS, vanilla JavaScript, Node `node:test`, Supabase Edge Functions на TypeScript/Deno, Supabase PostgreSQL, private Storage, Telegram Web App `initData`.

**Спецификация:** `README.md`, `ARCHITECTURE.md`, `brief.md`, `tg-app/docs/superpowers/specs/2026-09-02-product-group-variants-design.md`, `tg-app/docs/superpowers/specs/2026-09-02-admin-variant-and-saving-design.md`.

## Глобальные ограничения

- Не добавлять фреймворк, сборщик, npm-зависимости или новый сервер приложений.
- Интерфейс и пользовательские сообщения остаются на русском языке.
- `initDataUnsafe` нельзя использовать для авторизации, оплаты или доступа продавца.
- Секреты, токены, service-role key, настоящий Telegram ID и настоящий `initData` не записывать в код, Git, тестовые логи или документацию.
- Сохранять минимум 44×44 px для интерактивных элементов, учитывать ширины 320, 375 и 430 px, safe areas, светлую/тёмную тему и `prefers-reduced-motion`.
- Черновик может быть неполным; публикация должна оставаться строгой.
- Корзина не является резервом товара. Настоящая оплата считается успешной только после серверного callback платёжного провайдера.
- После каждого изменения кода обновлять относящиеся `README.md`, `ARCHITECTURE.md`, `CHANGELOG.md` и `.env.example`, если меняется конфигурационный контракт.
- Не выполнять `git commit`, `git push` или публикацию без отдельного запроса после preview и проверок.

## Карта файлов

- `tg-app/app.js` — состояние, синхронизация buyer/seller, события и экраны.
- `tg-app/api.js` — сетевой контракт и нормализация ответов.
- `tg-app/core.js` — чистая логика групп, статусов, корзины и валидации.
- `tg-app/tests/api.test.js` — тесты клиентского API.
- `tg-app/tests/app-smoke.test.js` — статические проверки runtime-потоков.
- `tg-app/tests/core.test.js` — чистая бизнес-логика.
- `supabase/functions/admin-api/index.ts` — защищённые действия продавца.
- `supabase/functions/catalog-api/index.ts` — публичный опубликованный каталог.
- `supabase/functions/_shared/admin-product.ts` — серверная валидация публикации.
- `supabase/functions/_shared/supabase.ts` — серверный клиент и безопасные ответы.
- `supabase/functions/_shared/telegram-auth.ts` — проверка Telegram `initData`.
- `supabase/functions/tests/` — серверные unit-тесты.
- `supabase/migrations/` — схема, RPC, RLS и индексы.
- `README.md`, `ARCHITECTURE.md`, `CHANGELOG.md`, `.env.example` — синхронная документация.
