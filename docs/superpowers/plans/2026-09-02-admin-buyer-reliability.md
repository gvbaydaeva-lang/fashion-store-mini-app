# Надёжность админ-панели и каталога — план внедрения

> **Для AI-агента:** перед выполнением используй `superpowers:subagent-driven-development` или `superpowers:executing-plans`. Выполняй задачи по порядку, отмечай каждый пункт `- [x]` только после проверки. Не делай commit/push без отдельного разрешения владельца.

**Цель:** продавец не теряет введённый товар, может сохранить неполный черновик и добавить новый цветовой вариант, а покупатель видит опубликованные товары с честной доступностью размеров и остатков.

**Архитектура:** остаётся vanilla-JS Mini App. Локальный черновик — восстановление формы, сервер — источник истины для опубликованных товаров и остатков. Товар является группой цветовых карточек; каждая карточка имеет собственные фотографии, размеры и остатки. Сервер сохраняет карточку, варианты и подтверждённые пути изображений согласованно.

**Стек:** HTML, CSS, vanilla JavaScript, Node `node:test`, Supabase Edge Functions на TypeScript/Deno, PostgreSQL, private Supabase Storage, Telegram Web App `initData`.

**Спецификация:** [`2026-09-03-reliable-admin-catalog-requirements.md`](../research/2026-09-03-reliable-admin-catalog-requirements.md).

## Глобальные ограничения

- Не добавлять React, Medusa, Vendure, Saleor, GraphQL, сборщик, npm-зависимости или новый сервер приложений.
- Черновик можно сохранить без фотографии и с незаполненными обязательными полями; публикация без фотографии запрещена.
- Опубликованный товар с остатком `0` остаётся в каталоге, но не добавляется в корзину.
- Размер доступен только если `enabled !== false` и целый `stock > 0`.
- Не хранить большие фотографии как единственную копию в `localStorage`; использовать IndexedDB до подтверждённой загрузки.
- Не принимать `data:` URL, произвольный внешний URL, токены, `initData` или service-role key как данные товара.
- Не показывать пользователю PostgreSQL, Supabase, stack trace, имена таблиц и constraint.
- Все интерактивные элементы не меньше 44×44 px; проверить 320, 375 и 430 px, safe areas, светлую/тёмную тему.
- После изменения кода обновить относящиеся `README.md`, `ARCHITECTURE.md`, `CHANGELOG.md` и `.env.example` только при изменении имён переменных.

## Карта файлов

- `tg-app/app.js` — состояние редактора, автосохранение, восстановление, seller/buyer события.
- `tg-app/api.js` — сетевой контракт, idempotency и безопасные ошибки.
- `tg-app/core.js` — чистые правила цветов, вариантов, доступности и публикации.
- `tg-app/styles.css` — статусы черновика, ошибок и недоступных вариантов.
- `tg-app/tests/` — регрессии UI, API и бизнес-логики.
- `supabase/functions/admin-api/index.ts` — авторизованные операции продавца.
- `supabase/functions/catalog-api/index.ts` — только опубликованный каталог.
- `supabase/functions/_shared/admin-product.ts` — серверная проверка публикации и payload.
- `supabase/functions/_shared/supabase.ts` — транзакционные вызовы и безопасное отображение ошибок.
- `supabase/migrations/20260903120000_reliable_admin_product_save.sql` — атомарное сохранение товара, вариантов и image metadata, если проверка схемы подтвердит необходимость RPC.
- `README.md`, `ARCHITECTURE.md`, `CHANGELOG.md` — документация фактически реализованного поведения.

## Критерий готовности

План выполнен, когда автоматические тесты проходят, серверная схема подтверждена, а реальный продавец может создать неполный товар, закрыть Mini App без потери данных, восстановить его, добавить независимый цветовой вариант, сохранить и опубликовать заполненную карточку. Покупатель видит опубликованный товар без остатков, но не может заказать нулевой или выключенный размер.

## Условия остановки

- При неизвестной причине server error сначала получить безопасный код операции и серверный лог; не маскировать проблему blind retries.
- При неподтверждённых Telegram Secrets, allowlist, миграциях или Storage не публиковать.
- При конфликте с другого устройства сохранить обе версии и остановиться до решения пользователя.
- Не расширять этот план оплатой, ботом, доставкой или новым фреймворком: это отдельные задачи.
