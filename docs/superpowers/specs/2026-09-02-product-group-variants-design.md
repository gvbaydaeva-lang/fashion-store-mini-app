# Склейка товара с самостоятельными цветовыми вариантами — дизайн

## Цель

Один товар на маркетплейсе может иметь несколько самостоятельных цветовых вариантов. В общем каталоге каждый цвет показывается отдельной карточкой. При открытии любой карточки покупатель остаётся на одном экране товара и переключает цвет без навигации назад; при этом меняются фото, цена, описание, размеры и остатки выбранного цвета.

## Термины

- **Склейка** — объединение связанных вариантов одной модели товара.
- **Вариант товара** — самостоятельная карточка конкретного цвета внутри склейки.
- **Размерный остаток** — количество для одного размера одного варианта товара.

## Хранение

Текущая запись `products` остаётся склейкой и хранит статус, общую категорию и связь вариантов. Новая таблица `product_options` хранит редактируемые поля отдельного варианта: название, цену, старую и оптовую цену, артикул, поставщика, описание и характеристики, цвет и порядок показа. Таблицы `product_option_images` и `product_option_sizes` хранят фотографии и размерные остатки этого варианта.

При миграции каждый существующий товар получает один вариант. Его фото, цена, описание, цветовые размеры и остатки переносятся в этот вариант. Товар не удаляется и не исчезает из опубликованного каталога.

## Редактор продавца

В редакторе склейки отображается одна полная карточка варианта. Кнопка называется **«Добавить вариант товара»** и добавляет следующую полную карточку: фото, название, цену, оптовую цену, описание, цвет, размеры и остатки. Поле называется только **«Цвет»**. Продавец может ввести несколько ручных названий одного цвета через запятую, но интерфейс не использует слово «синонимы».

Все карточки вариантов располагаются в одной мобильной колонке: одинаковая ширина, `box-sizing: border-box`, без отрицательных внешних отступов и горизонтального сдвига. После нажатия кнопки новая карточка становится видимой и получает фокус на поле «Цвет».

Черновик сохраняется с любым количеством незаполненных полей и вариантов. Публикация требует у каждого добавленного варианта: фото, название, цену, описание, оптовую цену, цвет, хотя бы один размер и целый остаток от нуля у включённого размера. Категория, артикул, старая цена и поставщик необязательны.

## Каталог и карточка покупателя

`catalog-api` возвращает опубликованные склейки с вложенными вариантами. Клиент разворачивает каждую склейку в каталоговые карточки: по одной для каждого варианта, используя его первое фото, цвет, цену и наличие. Ссылка любой такой карточки содержит идентификаторы склейки и выбранного варианта.

На экране товара кнопки цветов переключают активный вариант без закрытия карточки или скачка прокрутки. Галерея, цены, описание, доступные размеры и остатки берутся только из активного варианта. Добавление в корзину сохраняет выбранный вариант, цвет и размер.

## API и безопасность

`admin-api` принимает и возвращает склейку с массивом вариантов. Доступ продавца остаётся защищён текущей серверной проверкой raw Telegram `initData`; новые таблицы включают RLS и не дают прямой записи анонимным пользователям. `catalog-api` раскрывает только опубликованные склейки и их опубликованные варианты с одноразовыми ссылками на изображения.

## Проверка

Автоматические тесты должны подтверждать: перенос старого товара в единственный вариант, отдельные каталоговые карточки для цветов одной склейки, переключение варианта без навигации и разные фото/цены/размеры, а также свободное сохранение черновика и строгую публикацию. После публикации выполняются проверки JavaScript, Node-тесты, тесты Edge Functions и проверка опубликованного Pages-asset. Проверку в Telegram на iPhone нельзя заявлять выполненной без реального устройства.
